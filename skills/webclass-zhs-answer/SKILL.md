# webclass-zhs-answer

## 1. 用途

消费 **studentReviewTestOrExam 复习考试页的浏览器会话 + 每题答案** → 产出
**勾选完成并切题保存的答题卡（答题进度 25 → 50 → 75 → 100%）、提交后的判题摘要（已答对 n / 总题数、掌握度）** → 在 stage **2** 被调用。

**什么时候用**：

- 一份 4 题量级的知识点练习/复习卷要全部答完并按用户要求提交。
- 已有一份确定的答案表（例如 A、ABCD、C、C），需要逐题点选且不想误触「错题反馈」「重新答题」等破坏性入口。
- 需要留下逐题截图证据（答题过程、判题结果）用于交付或复盘。

**什么时候别用**：

- 答案还没定、需要讨论时 —— 先定答案，再用本技能。
- 页面不是复习/考试页（视频课、目录、讨论区）—— 走 `webclass-zhs-drive`。
- 没有浏览器桥（`browser_*` 工具不可用）—— 本技能只通过浏览器工具操作。

## 2. CRITICAL

> 每条都是「做了就会坏」。没有证据不许改这一节。

1. **点选后必须截图复核**。点击通常返回「无可见变化」（前端事件已生效但 DOM diff 不报），
   勾选状态只能靠 `browser_screenshot` / 快照确认；只信截图，不信 diff 文本。
2. **切题才保存**。答题进度只在点「上一题 / 下一题」后递增（0 → 25 → 50 → 75 → 100%）；
   选完选项不切题 = 未保存。每题选完必须切一次题。
3. **最后一题「下一题」是灰的**，用「上一题」触发保存；否则进度停在 75%，
   提交后可能少判一题。
4. **翻页可能跨卷**。在卷首点「上一题」或在异常边缘翻页时，URL 的 `paperId` / `examPaperId`
   会切换成另一张卷（实测 397339492 → 450609616），题号与选项顺序全部变成新卷的。
   每次翻页后核对 `paperId` 与开工值；不一致立即停手、`browser_back` 回退，不要在新卷上继续作答。
5. **提交不可逆，只有用户明确说「提交」才点「提交作业」**。提交后页面跳到知识点分析页
   （「总题数 4 / 已答对 4」「掌握度」），立即截图留证。
6. **绝不主动点「错题反馈」「重新答题」「AI答题辅导」「收藏为薄弱题」** ——
   它们会进入新的学习流或重置尝试记录。
7. **多选逐项点，单选点 `li`、多选点 `label`**。每点一项截图一次；全部勾完再切题。
8. **提交后进知识点分析页核对「已答对 n / 总题数」**。掌握度是加权值（4/4 全对显示 97%），
   不要用掌握度百分比判断对错。
9. **「去提升」在闭环里出现两次**：知识点页「去提升 ›」进「历史提升掌握度」报告页，
   报告页标题下方「去提升 →」才进练习卷。少点一次会停在报告页。
10. **判断题按单选处理**（A 对 / B 错，点 `li`），不是多选。
11. **选项必须逐个点、逐个核验**；一次 `browser_console_eval` 连点多个选项会丢状态
   （实测 ABCD 只生效 D，提交判 0/1）。核验看 `el-checkbox is-checked` / `el-radio is-checked`。
12. **提交后用「已答对 n / 总题数」复核**：0/n 优先怀疑点击没生效，而不是答案错。
13. **进「去提升」前必须先过「必学资源全绿」闸门**：底部「必学资源」每张卡右下角都要有
    绿色「已完成」角标（DOM：`.basic-info-video-card-container` 内的 `.finished-icon`）。
    缺任意一张 → 先按 `references/boost-loop-recipe.md` 第 0 步补看，刷新复查通过后才点「去提升」。
14. **「已完成」只认刷新后的角标**：拖进度条到末尾 5s 后，必须等播放真正结束
    （`video.ended === true` 或播放器进度条走到头）再刷新复查；只看到 100% 或播放器变灰不算数。
15. **掌握度 < 90 必须重做**：提交后读分析页的「掌握度」，**< 90 就再走一遍本卷**
    （重进「去提升」→ 重新作答 → 提交）。同一节最多重做 2 次；两次后仍 < 90 就记下
    「未达标 + 最好成绩」，继续下一节，**不许静默跳过**。
    判据用「掌握度」（当前加权值），「最好成绩」另记一行参考，两者都写进台账。
16. **每节都要落台账**：`point / answers / correct / total / mastery / best / attempts`。
    台账只追加，重做写新行，不覆盖旧行。

## 3. 工作流

1. **定位**：`browser_snapshot` 读标题 / URL / 题型；从 URL 记录起始 `paperId`、`classId`、`pointId`。
1a. **前置闸门（必做，不通过不进卷）**：在知识点学习页检查底部「必学资源」——
    逐张卡读 `.finished-icon`，**全都存在**（绿色「已完成」）才点「去提升」；
    缺哪张就先点开那张视频，把进度条拖到末尾 5s、等播放结束、刷新复查，见
    `references/boost-loop-recipe.md` 第 0 步。只点「去提升」不做这步 = 在资源未完成的知识点上刷分，
    掌握度提升会被平台按未完成资源打折。
2. **逐题作答**：用 `browser_snapshot {query:{text:"选项文本"}}` 拿 selector →
   `browser_click` 点单选 `li` 或多选 `label` → `browser_screenshot` 复核勾选。
3. **保存**：点「下一题」→ `browser_wait {ms:800}` → 快照确认进度 +25% 且下一题已渲染。
4. **最后一题**：点「上一题」触发保存，确认进度 100%，再点「下一题」回到末题复核选项仍在。
5. **全卷复核**：用答题卡 1–4 逐题截图，确认每题选择与答案表一致。
6. **提交**：用户明确授权后点「提交作业」，截图判题摘要。
6a. **达标判据**：读分析页「掌握度」——**取圆环里的大数字（`.charts-label-rate`）**；
    紧跟其后的那个百分比是「本次变化值」，不是掌握度（实测见过 97% 掌握度 + 0% 变化）。
    ≥ 90 记一条台账进下一节；< 90 立刻重做本卷（重新「去提升 ×2」→ 作答 → 提交），
    最多 2 次，仍不达标则记「未达标」+「最好成绩」后继续。
7. **交付**：报告每题最终选择 + 判题结果；旧卷/新卷分开写清（哪张已判、哪张是重答）。
8. **多知识点闭环**：按 `references/boost-loop-recipe.md` 六步循环 ——
   左侧目录选「下一门课」→「去提升 ›」→「去提升 →」→ 作答 →「提交作业」→ 分析页 `←` 返回 → 重复。

## 4. 示例

```text
browser_snapshot                                   # 1) 定位；记下 paperId=397339492
browser_snapshot {query:{text:"实践是认识的来源"}}   # 2) 取选项 selector（li 或 label）
browser_click {selector:"... ul:nth-child(2) > li:nth-child(1)"}   # 单选点 li
browser_screenshot                                 # 3) 复核（点击常报「无可见变化」）
browser_click {selector:"... div:nth-child(2) > span:nth-child(2)"} # 下一题
browser_wait {ms:800}
browser_screenshot                                 # 4) 确认进度 +25%、新题已渲染
```

多选（如第 2 题答案 ABCD）：依次点 `label:nth-child(1..4)` 四个 label，每点一个截图一次。

末题（第 4 题）：点「上一题」（不是灰的「下一题」）触发保存，进度应到 100%。

提交：用户说「提交」之后才点右上角「提交作业」，预期跳转知识点分析页并显示「已答对 4 / 总题数 4」。

前置闸门（进卷前）：

```text
browser_console_eval  [...document.querySelectorAll('.resources-section')][0]
                      .querySelectorAll('.finished-icon').length   # 与卡片数比对
# 缺卡 → 点该视频卡 → 拖 .vjs-progress-holder 到末尾 5s → 等 video.ended → reload → 复查
```

多知识点闭环（去提升）：左侧目录点「下一门课」→「去提升 ›」→「去提升 →」→ 作答 →「提交作业」→
分析页显示「已答对 2 / 总题数 2」→ 点左上角 `←` 返回 → 重复。

## 5. 故障排除

| 症状 | 根因 | 处置 |
|---|---|---|
| 点击返回「无可见变化」 | DOM diff 不报但事件已生效 | 截图复核，别重点 |
| 答题进度不涨 | 选完没切题 | 点上一题/下一题触发保存 |
| 末题进度停在 75% | 「下一题」灰、未保存 | 点「上一题」触发保存 |
| 翻页后题号/选项对不上 | 跨卷（`paperId` 变了） | `browser_back` 回退并核对 paperId，别在新卷继续 |
| 复习模式下错题无改法 | 即时判题，错选后无编辑入口 | 见 `references/page-mode-matrix.md`「即时判题」 |
| 提交按钮没反应/弹窗 | 确认框或接口慢 | 截图，交用户处理 |
| 同名题干出现两处 | 跨卷残留或答题卡缩略 | 用 query 命中数确认，只点当前题 |
| 提交后页面空白 | 分析页资源慢 | 重试一次快照，仍空则报 |
| 必学资源卡没有绿勾 | 视频没看完（无 `.finished-icon`） | 进视频页：拖进度条到末尾 5s → 等播完 → 刷新复查 |
| 拖到末尾 5s 后刷新仍无绿勾 | 平台按心跳记进度，末段还没上报 | 再等 10–20s 或从末尾前 1min 重播一次，再刷新 |
| 「去提升」点了却没进报告页 | 前置闸门未过，按钮被拦 | 先补齐必学资源绿勾，再点两次「去提升」 |
