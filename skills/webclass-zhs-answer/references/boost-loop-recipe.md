# 提升闭环配方（去提升 → 练习 → 提交 → 下一门课）

> 在「知识点学习页」（课程页，左侧知识模块目录）上，对一门课逐知识点做提升练习时使用。
> 一次闭环 7 步（含第 0 步前置闸门）；目标是用最少的浏览器调用完成一轮。

## 1. 完整路径（7 步）

0. **前置闸门：必学资源全绿**（每次点「去提升」之前都要过一遍）
   - 判定：底部「必学资源」区块里，**每张**卡右下角都有绿色「已完成」角标。
     DOM 上就是 `.resources-list .basic-info-video-card-container` 内是否存在 `.finished-icon`。
   - 一次 eval 拿全（只读）：
     ```js
     [...document.querySelectorAll('.resources-section')].map((s) => ({
       title: s.querySelector('.resources-detail-title')?.innerText.trim(),
       cards: s.querySelectorAll('.basic-info-video-card-container').length,
       done: s.querySelectorAll('.finished-icon').length,
     }))
     ```
     `cards === done` 且 `title` 为「必学资源」的那一段通过，才允许进第 1 步。
   - 有未完成卡：点那张卡 → 主区切换成 video.js 播放器 → 点 `.vjs-progress-holder`
     靠右的位置把进度拖到 **`duration - 5s`** → 等播放真正结束
     （`video.ended === true`，或播放器进度条走到头、时间与 duration 齐平）
     → `browser_reload` → 重新读上面的 eval 复查。
   - 复查仍缺：再等 10–20s 刷新一次（平台按心跳上报，末段可能有延迟）；
     两次不过就 `wait_human`，并把该小节名报给用户，**不要**带着未完成资源去刷卷。
   - 红线：**不许用脚本写 `video.currentTime`**，也不许改 `playbackRate` 之外的东西；
     只能操作播放器自己的进度条。这是「像人一样看完」，不是伪造进度。
1. **知识点学习页**（URL 含 `learn` / 左侧有知识模块目录）：
   点左侧目录里的「下一门课」（= 知识单元下的下一个知识点，如「马克思主义对青年成长有什么指导意义」）。
   主区加载该知识点的视频/PPT，底部出现 **「去提升 ›」** 按钮（旁边是「知识点最高掌握度 0%」）。
2. 点 **「去提升 ›」**（第 1 次）→ 进入 **「知识点学习报告 / 历史提升掌握度」** 页：
   顶部是知识点名 + 「最高掌握度 0%」，中间「掌握度历史记录」（首次为「暂无数据」）。
3. 该页标题下方再点 **「去提升 →」**（第 2 次）→ 进入 **「知识点练习默认部分」复习卷**（`studentReviewTestOrExam`）。
4. **作答**：单选点 `li`、多选点 `label`、判断题按单选（A 对 / B 错）。
   答题进度只在切题后递增；末题「下一题」灰 → 点「上一题」触发保存到 100%。
5. 点 **「提交作业」** → 跳到 **知识点分析页**：圆环掌握度、「总题数 n / 已答对 n」、「查看作答记录与解析」。
5a. **达标闸门（掌握度 < 90 重做）**：读分析页「掌握度」——
    - ≥ 90：记账，进第 6 步；
    - < 90：从第 3 步重来（报告页再点「去提升 →」→ 重新作答 → 提交），最多 2 次；
      两次仍未达标，记「未达标 + 最好成绩」，照样进第 6 步（不卡住整条链路）。
    注意「掌握度」是加权值，「最好成绩」是最高分，两者分开记。
6. **返回**：点分析页左上角 `←` → 回到知识点学习页 → 从第 1 步重复。

## 2. 观察证据（每步应看到什么）

| 步骤 | 应看到 |
|---|---|
| 第 0 步（前置闸门） | 必学资源卡 `cards === done`，全是绿勾「已完成」；否则先补看视频并刷新复查 |
| 选下一门课 | 主区标题变成新知识点名 |
| 去提升（第 1 次） | 面包屑「知识点学习报告 / 历史提升掌握度」 |
| 去提升（第 2 次） | 标题「知识点练习默认部分」+ 答题卡 1……n |
| 作答完成 | 答题进度 100% |
| 提交 | 圆环掌握度 + 「已答对 n / 总题数」 |

## 3. 减少 API 调用的批处理

1. **先定位再连点**：一次 `browser_snapshot {query:{text:"选项文本"}}` 拿 selector，然后连续 `browser_click`，
   中间不要再 snapshot；点完后**一次截图**复核全部勾选。
2. **一图多验**：截图能同时核对 4 个勾选、进度、题号，不必逐项验。
3. **选项必须一个一个点**（`browser_click` 点 `label`/`li`，一次调用一个），
   **禁止在一次 `browser_console_eval` 里连点多个选项**：实测一次 eval 连点 A–D，
   DOM 上 `input.checked` 全为 true，但 Vue 状态只同步了最后一个，提交后判 0/1。
   每次点完可用一次 eval 批量校验（只读）：

```js
// 只读校验：四行都应返回 is-checked
[...document.querySelectorAll('#app-content label')].map(l => l.className)
```
   单选看 `el-radio is-checked`，多选看 `el-checkbox is-checked`；与预期不符就补点对应项。
4. **提交后一次读页面文本**（`document.body.innerText`）确认「总题数 n / 已答对 n」：
   0/n 说明有点击没生效，别当成答案错，先重答。
5. **单题卷**（答题卡只有 1 题）上下题按钮都灰、答题进度一直 0% 是正常的，提交后才变 100%。

## 4. 跨卷防御（重要）

- 同一份复习卷内，**「上一题 / 下一题」不应改变 URL 的 `paperId`**。
  变了 = 已离开本卷（边界翻页可能加载相邻知识点的卷），立即核对题目是否还是本知识点。
- 从「返回」→ 目录 → 选下一门课 → 再「去提升」：`paperId` **必然变化**，这是正常的，新知识点 = 新练习卷。
- 每个知识点的练习卷独立判题，互不影响；上一份的错题不影响下一份。

## 5. 异常处置

| 症状 | 处置 |
|---|---|
| 点「去提升」后没进报告页 | 再点一次；确认 URL 变化 |
| 必学资源卡无绿勾 | 视频没看完：点卡 → 拖到末尾 5s → 等 `video.ended` → 刷新复查 |
| 拖到末尾 5s 刷新后仍无绿勾 | 心跳没上报：等 10–20s 再刷新；两次不过交人（`wait_human`） |
| 报告页「暂无数据」 | 正常（该知识点首次提升） |
| 提交后圆环显示「最好成绩」 | 多次提交会累计，掌握度是加权值，非正确率 |
| 返回后左侧目录没展开 | 展开对应知识单元再选下一门课 |
