# 作业答题操作手册（行为模式）

> 本文是一次真实会话沉淀出的完整行为模式：页面地图 + 主循环 + **怎么选答案** + 省调用节奏 + 安全边界。
> 供另一个 agent 直接照做。配套技能：`webclass-zhs-answer`。

## 0. 目标与角色

- 目标：在智慧树「新形态课程」里，对每个知识点完成 **去提升 → 练习 → 提交 → 下一门课** 的循环，
  并把每题答案选对、留档判题结果。
- 角色：只做浏览器操作（点击 / 读取 / 提交）。**答案对错由模型按教材判断**，
  但「提交」必须已获用户授权（或用户已明确说「重复动作」= 授权循环提交）。
- 输出：每轮报告「知识点名 + 每題选择 + 已答对 n/总题数 + 掌握度」。

## 1. 页面地图

| 页面 | URL 特征 | 作用 |
|---|---|---|
| 知识点学习页 | `ai-smart-course-student-pro.zhihuishu.com/learnPage/...`；左侧知识模块目录；主区视频/PPT；底部「去提升 ›」 | 选课、进入提升 |
| 历史提升掌握度页 | `.../masteryHistory/...`；面包屑「知识点学习报告 / 历史提升掌握度」 | 过渡页，标题下方有第二个「去提升 →」 |
| 知识点练习卷 | `studentexamcomh5.zhihuishu.com/studentReviewTestOrExam/...` | 答题、提交（单选 `li`、多选 `label`） |
| 知识点分析页 | `.../point/...`；圆环掌握度 +「总题数 n / 已答对 n」 | 提交后判题结果 |
| 题目预览/解析页 | `.../examPreview/...` | 只读：每题对错 + 参考答案 |

> 同一份卷内 `paperId` 不变；换知识点后 `paperId` 一定变，属正常。

## 2. 主循环（七步）

0. **前置闸门**：回学习页后先看底部「必学资源」——每张卡右下角都要有绿色「已完成」
   （`.basic-info-video-card-container` 里有 `.finished-icon`）。缺卡就先看完再进卷，见 §2.1。
1. 分析页左上角 `←`（`div.backup-icon`）→ 回知识点学习页。
2. 左侧目录展开对应知识单元，点「下一门课」（下一个知识点）。
3. 主区点 **「去提升 ›」**（第 1 次）→ 报告页。
4. 报告页点 **「去提升 →」**（第 2 次）→ 练习卷。
5. 答题：选项逐个点；核对 `is-checked`；切题保存到 100%（单题卷直接提交）。
6. 点「提交作业」→ 分析页核对「已答对 n / 总题数」→ 回到第 1 步。

### 2.1 必学资源补看（第 0 步不通过时）

1. 点缺的那张视频卡（`.resources-list .basic-info-video-card-container` 里没有 `.finished-icon` 的那张）
   → 主区变成 video.js 播放器（`video-js vjs-default-skin`）。
2. 点 `.vjs-progress-holder` 靠右位置，把播放头拖到 **`duration - 5s`**。
   校验：`video.currentTime >= video.duration - 6`。
3. 等播放自然结束：`video.ended === true`（通常 <10s）。
4. `browser_reload` 刷新 → 重新读绿勾计数复查（`cards === done`）。
5. 两次刷新仍无绿勾 → `wait_human`，把小节名报给用户。**不要**带着未完成资源去点「去提升」。

> 红线：只能用播放器进度条，不许脚本写 `video.currentTime`、不许伪造心跳。

## 3. 怎么选（答案判定规则）

### 3.1 题型识别

- 单选：选项 `li`，圆点。
- 多选：选项 `label`，方框。
- 判断题：也是单选，A 对 / B 错。

### 3.2 单选（含多选中的"唯一表述"）

按教材原句对应，常见对应关系（马原经验）：

| 题干关键词 | 选项 |
|---|---|
| 实践是认识的…（来源/动力/目的/检验标准） | 看"基础/来源"→来源；"推动"→动力；"为了"→目的；"证明"→检验标准 |
| 马克思主义的精髓 | 实事求是 |
| 马克思主义的生命力/当代价值 | 认识工具 + 行动指南 + 科学真理 |
| 列宁"先进战士"/"革命理论" | 先进理论 |
| 真理的绝对性/相对性 | 统一 |

### 3.3 判断

- 表述与教材正面结论一致 → 对；出现「所有」「任何」「唯一」「完全」等放大词且教材无此说法 → 错。
- 例：「马克思主义为青年成长成才指明正确方向、提供思想滋养」→ **对**。

### 3.4 多选（最容易错，重点）

教材型多选题的两种结构：

1. **要点罗列型**（"主要体现在 / 正确的是 / 有哪些"）——选项全部是教材正面要点，
   且通常一一对应教材该节列出的 n 条 → **全选**。
   例：「马克思主义日益焕发生命力，主要体现在」→ A、B、C、D；
   「当代青年应如何自觉学习和运用马克思主义」→ A、B、C、D（参考答案实测 ABCD）。
2. **含干扰项型**——某个选项与题意相悖（如"能指引人们解决所有问题"这种绝对化）
   → 排除该选项，其余全选。

判定口诀：**先数教材要点条数 → 再对照选项 → 无极端词全选，有极端词剔掉那一个**。

### 3.5 提交前自查（必做）

- 用一次只读 eval 核对：`el-checkbox is-checked` 数量 = 预期勾数；
  与预期不符先补点，再提交。
- 答题进度：多题卷切题后 25/50/75/100；单题卷 0% 正常，提交后变 100%。

### 3.5b 达标闸门（掌握度 < 90 重做）

- 提交后读分析页**掌握度**：**圆环大数字 `.charts-label-rate`** 才是掌握度，紧跟的百分比是「本次变化值」，别取错。≥ 90 收工；< 90 重进本卷重做，**最多 2 次**。
- 两次仍 < 90：记「未达标」+「最好成绩」，继续下一节，不要在一节上死磕。
- 「掌握度」是加权值、会记住历史差卷；「最好成绩」是最高分——台账两个都要写，
  否则后面复盘分不清是「答错了」还是「被旧分数拖累」。

### 3.6 提交后核对与补救

- 分析页「已答对 n / 总题数」= 最终判分依据；掌握度是加权值，别用百分比判对错。
- 出现 0/n：优先怀疑点击丢失（不是答案错）。补救路径：
  预览页「重新答题」或报告页再点「去提升」重做 → 逐项核对后重新提交。
- 拿不准的题，可在预览页看「参考答案」校准后再重做。

## 4. 省调用节奏（减少 API 调用）

| 做法 | 说明 |
|---|---|
| 一次 `browser_console_eval` 读多信息 | 同时返回 URL、`body.innerText` 摘要、`label.className` |
| 一次 `browser_snapshot {query}` 只定位选项 selector | 拿全 4 个 label 的 selector |
| 点击用 `browser_click` 逐个（禁止单次 eval 连点） | 连点会丢 Vue 状态，提交判 0 分 |
| 截图只在关键节点 | 答完一张、提交后一张；不要每步截图 |
| 跨页导航用 `browser_wait 800–2500` | 等渲染，不轮询 |
| 页面结构同型可复用 selector 模式 | `... label:nth-child(1..4)` / `div:nth-child(2) > span:nth-child(2)`（下一题） |

## 5. 安全边界（红线）

- 不点「错题反馈」「AI答题辅导」「收藏为薄弱题」（会进新学习流）。
- 未获授权不点「提交作业」；用户说「重复动作」即视为循环内授权。
- 不碰视频进度条、不调平台接口；不做反检测。
- 循环循环到用户喊停为止；每 N 轮（如每 3–4 门课）汇报一次进度。

## 6. 故障排除

| 症状 | 处置 |
|---|---|
| 点击报 "message channel closed" | 重试一次；仍失败换 selector 或先快照刷新 |
| 提交后 0/n | 点击丢失 → 重答（见 3.6） |
| 翻页后题号全变 | 跨卷（paperId 变）→ 核对是否仍在目标知识点 |
| 截图报 "window not focused / stale frame" | `browser_follow_tab {activate:true}` 后再截 |
| 「去提升」只点了一次 | 停在报告页，点标题下方第二次「去提升 →」 |
| 必学资源无绿勾 | 视频没看完 → 按 §2.1 补看（拖到末尾 5s → 等 ended → 刷新复查） |
| 补看后刷新仍无绿勾 | 心跳延迟 → 等 10–20s 再刷新；两次不过交人 |

## 7. 给下一个 agent 的交接

1. 先读 `SKILL.md` 的 CRITICAL 与 `references/boost-loop-recipe.md`，再读本文。
2. 用户指令形如「返回 → 目录 → 下一门课 → 去提升 ×2 → 重复」时，按 §2 循环执行。
3. 答案判定按 §3；提交后必须核对「已答对 n / 总题数」，异常按 §3.6 补救。
4. 工具节奏按 §4，别省略「提交前自查」与「提交后核对」两个校验点。
5. 每轮结束向用户汇报：知识点名 / 每题选择 / 判题结果 / 掌握度。
